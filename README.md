# hypex

Exploring the role of hypernetworks in few-shot meta reinforcement learning.

**Central question:** does the *diversity* of a task distribution — measured with
Wasserstein Task Embeddings (WTE) — predict when **full hypernetwork (HN)
conditioning** of the policy beats **head-only** or **FiLM** conditioning?
Two experiment families test this:

| Notebook | Environment | Reward | Script |
|----------|-------------|--------|--------|
| `scripts/exp2.ipynb` | GridNavi 6×6 | sparse | (predecessor of `run_exp.sh`, see below) |
| `scripts/exp2_copy.ipynb` | GridNavi 6×6 | dense (distance-based) | `bash_scripts/run_exp.sh` |
| `scripts/exp9.ipynb` | HalfCheetahVel | velocity-tracking | `bash_scripts/run_chevel.sh` |

## Setup

Create and activate the conda environment from `env.yml`:

```bash
conda env create -f env.yml
conda activate adv_rl
```

To refresh packages later:

```bash
conda env update -f env.yml --prune
```

Notebooks can be run from the repo root or from `scripts/` (they resolve
`CODE_DIR` from the working directory). Run cells top-to-bottom; re-run the
data-collection cell only to regenerate the saved SARS arrays under `data/`.

## How the WTE metric is calculated (shared by exp2 / exp2_copy / exp9)

Implemented by `Detect` in `scripts/detect.py`; both notebooks use the same
protocol except where noted.

1. **Collect SARS tuples per task.** For each task (a goal cell in GridNavi, a
   target velocity in HalfCheetahVel), roll out a *random-action* policy and
   save rows `[s, a, r, s']` as `.npy` files under `data/`.
2. **Reference set.** `detect.set_reference(...)` draws
   `REFERENCE_NUM = 100` random reference rows of the same `[s, a, r, s']`
   shape (fixed `torch.manual_seed(98)`, shared by all tasks in a notebook).
3. **LWE embedding per task.** `detect.lwe(sar, ACTION_DIM)`:
   - preprocesses the batch (states and next-states normalised; actions
     one-hot encoded for the discrete GridNavi, left continuous for
     HalfCheetahVel),
   - solves an optimal-transport problem (`ot.emd`, uniform marginals)
     between the task's SARS rows and the 100 reference rows,
   - returns the barycentric projection of the transport plan, flattened.
   Embedding dimension = `100 × (row dimension)` → **1000** for GridNavi
   (rows are 10-d: 2 + 5 + 1 + 2) and **4700** for HalfCheetahVel
   (rows are 47-d: 20 + 6 + 1 + 20).
4. **Within-distribution diversity.** Each task embedding is L2-normalised and
   the diversity of a task distribution (TD) is the **mean pairwise cosine
   distance** over its tasks:
   - `d_all` — mean of `1 − cos(eᵢ, eⱼ)` over all task pairs in the TD.
     This is an average, not a sum, so having more tasks does not
     mechanically inflate it.
   - `d_matched` — the same statistic averaged over *all* subsets of
     `PAIRWISE_SUBSET_SIZE = 4` tasks (a U-statistic), so TDs with different
     task counts (e.g. 36-goal TD4, or CheetahVel's 8 velocities) are
     compared at a matched subset size.
5. **Fair PCA variant.** Exactly 4 tasks per TD (evenly spaced) are pooled,
   L2-normalised, and projected with PCA to `PCA_DIM = 8`; `d_matched` is
   then recomputed in that 8-d space. **Caveat:** PCA is fit separately in
   each notebook, so PCA axes are *not* shared — compare orderings/spreads
   within one notebook, never absolute PCA values across notebooks.
   The 2-d PCA/LDA scatter plots are visualisation only.

The notebooks also report the cosine distance between TD *mean* embeddings
(between-TD similarity), which is a different quantity from the
within-TD diversity above.

## The three conditioning ablations (shared by all training)

All training uses the same RNN+HN / RL²-style backbone (`hyper/main.py`):
hypernetwork input = latent, decoder disabled, non-variational latent,
RL loss through the encoder, `pass_latent_to_policy True`. Only the
conditioning scope differs:

| Method | Flags | Meaning |
|--------|-------|---------|
| **full** | `--use_film False --policy_layers_hyper 1 1 1` | HN generates all policy-layer weights |
| **head** | `--use_film False --policy_layers_hyper 0 0 1` | HN generates only the final (head) layer |
| **film** | `--use_film True --policy_layers_hyper 1 1 1` | FiLM scale/shift conditioning (init_b) |

Training logs include `hn_weight_div/mean_pairwise_l2` (mean pairwise L2
between per-task mean actor weights generated by the HN; GridWorld runs
only). Note this raw L2 is **not** comparable across the three methods —
they generate parameter vectors of different sizes/semantics.

### HN weight divergence — what it measures, and its status

`hn_weight_div/mean_pairwise_l2` (tracker:
`hyper/utils/hn_weight_divergence.py`, enabled with
`--log_hn_weight_div True`) quantifies **how much the policy weights
generated by the hypernetwork change across tasks within a task
distribution**. At the end of each meta-episode, the tracker feeds the
task's latent through the HN, flattens the generated *actor* weights
(critic excluded), averages them per task, and every log interval records
the mean pairwise L2 distance between those per-task mean weight vectors
(plus the vectors themselves, saved under `hn_weight_div/iter_*.pt`).
A task distribution that demands more task-specific policies should force
the HN to move its generated weights further apart, so this statistic is
the training-time analogue of the WTE diversity probe: the expectation is
that more complex / more diverse distributions show greater weight change.

**Status:** implemented and logged for all GridWorld runs (sparse and
dense). **Not yet implemented for HalfCheetahVel** — the tracker is
grid-specific: it converts a 2-D goal `(gx, gy)` into a cell id via
`num_cells`, and HalfCheetahVel tasks are a continuous scalar velocity
with no `num_cells`, so simply adding `--log_hn_weight_div True` to
`run_chevel.sh` would crash. Implementing it requires a generic task key
(e.g. binning the target velocity), after which the CheetahVel runs would
need to be re-run (or probed offline from the saved checkpoints — see the
exp9 section). This is a diagnostic, not part of the headline
return comparison, so it is **not** a blocker; see the exp9 section for
whether/when it is worth doing.

## Experiment exp2 — GridWorld (sparse & dense)

### The MDPs

Both use `GridNavi` on a **6×6 grid, horizon H = 20, uniform random start**.
They differ *only* in reward:

- **Sparse** (`exp2.ipynb`): `+1` at the goal, `−0.1` otherwise
  (`distance_reward=False`).
- **Dense** (`exp2_copy.ipynb`): `+1` at the goal, else
  `−(Manhattan distance to goal)/6` (`distance_reward=True`).

Goal sets (task distributions), identical in both:

| TD | Goals | Description |
|----|-------|-------------|
| TD1 | (5,5), (5,4), (4,5), (4,4) | top-right cluster |
| TD2 | (3,3), (5,3), (3,5), (5,5) | mid/edge spread |
| TD3 | (0,0), (0,5), (5,0), (5,5) | four corners |
| TD4 | all 36 cells | every cell is a goal (dense notebook only) |

### WTE probe (notebooks)

Data collection enumerates every start cell: 36 starts × 20 steps =
**720 SARS rows per goal** (seed 42), saved under
`data/gridworld_sparse/task_dist{k}/` (exp2) and
`data/gridworld_dense6/task_dist{k}/` (exp2_copy). Then the shared WTE
protocol above (discrete actions → `one_hot=True`).

Results — raw within-TD diversity `d`:

| TD | Sparse `d` | Dense `d` |
|----|-----------:|----------:|
| TD1 | 0.0588 | 0.0541 |
| TD2 | 0.0558 | 0.0659 |
| TD3 | 0.0517 | 0.1182 |
| TD4 | — (not probed) | 0.0906 |

PCA-matched `d_matched` (each notebook's own joint PCA fit, 4 tasks/TD →
8 dims; do not compare across the two columns):

| TD | Sparse (12-task fit) | Dense (16-task fit) |
|----|---------------------:|--------------------:|
| TD1 | 1.1615 | 0.8324 |
| TD2 | 1.1176 | 0.9253 |
| TD3 | 0.9677 | 1.0965 |
| TD4 | — | 1.2381 |

Read: under the sparse reward all TDs have nearly *equal* diversity; under
the dense reward the raw ordering becomes TD3 > TD4 > TD2 > TD1.

### Training (full vs head vs film)

Registered envs (`hyper/environments/__init__.py`):

- Sparse: `GridNavi-TaskDist{1,2,3}-v0` (`--env-type gridworld_taskdist{k}`)
- Dense: `GridNavi-Dense6-TaskDist{1,2,3,4}-v0`
  (`--env-type gridworld_dense6_taskdist{k}`)

Hyperparameters (both): `policy_layers 32 32`, state/latent/task embedding
25, GRU hidden 256, `num_steps 60`, 16 processes, `max_rollouts_per_task 4`,
`lr_policy 7e-4`, `lr_vae 1e-3`, seed 73.

**Dense (current script):**

```bash
conda activate adv_rl
bash bash_scripts/run_exp.sh                                   # TD4→TD1 × full/head/film, 2M frames each
DISTS="3" RUNS="full head" bash bash_scripts/run_exp.sh        # subset
SEED=20 DISTS="4 3" RUNS="full head" bash bash_scripts/run_exp.sh  # extra seed
```

Logs → `logs_gridworld_dense6/logs_GridNavi-Dense6-TaskDist{k}-v0/grid_dense6_td{k}_rnn_{full,head,film}_*/`

**Sparse:** `run_exp.sh` now points at the dense envs. The completed sparse
sweep (TD1–TD3 × full/head/film, **4M frames**, logs in `logs_gridworld/`)
was run with the same script and hyperparameters against
`gridworld_taskdist{k}` / `GridNavi-TaskDist{k}-v0`. To re-run it, change
the three dense-specific lines in `run_exp.sh` (`env_type`, `env_name`,
`RESULTS_LOG_DIR`) to the sparse values and set `NUM_FRAMES=4000000`.

**Headline results** (last-10% mean Meta-Episode Return, seed 73):

| | TD1 full−head | TD2 full−head | TD3 full−head | TD4 full−head |
|---|---:|---:|---:|---:|
| Sparse | −1.80 | −0.35 | +0.63 | — |
| Dense | +2.26 | +2.83 | −0.51 | +4.79 |

Sparse: no conditioning effect anywhere (matching its equal WTE values).
Dense: a modest full advantage except on TD3 — the highest-raw-WTE TD —
which is the main open anomaly (all results are single-seed).

## Experiment exp9 — HalfCheetahVel

### WTE probe (`scripts/exp9.ipynb`)

Tasks are target velocities. The probe defines five distributions of
**8 velocities each** (`np.linspace`, inclusive):

| Probe TD | Velocity range |
|----------|---------------|
| 1 | [0.5, 0.75] |
| 2 | [0.75, 1.0] |
| 3 | [2.5, 2.75] |
| 4 | [2.75, 3.0] |
| 5 | [0.0, 3.0] (full range) |

Data: random actions in `HalfCheetahVelEnv` (episode length 200),
25 episodes → **5000 SARS rows per velocity**, rows are 47-d
`[s(20), a(6), r, s'(20)]`, saved under `data/chevel/task_dist{k}/`.
Same WTE protocol as exp2 except continuous actions → `one_hot=False`
(embedding dim 4700).

Results:

| Probe TD | Range | raw `d` | PCA `d_matched` |
|----------|-------|--------:|----------------:|
| 1 | [0.5, 0.75] | 0.0455 | 0.4360 |
| 2 | [0.75, 1.0] | 0.0610 | 0.7650 |
| 3 | [2.5, 2.75] | 0.0452 | 0.7782 |
| 4 | [2.75, 3.0] | 0.0640 | 0.8603 |
| 5 | [0.0, 3.0] | 0.0775 | 1.1297 |

Equal-width bands (TD1–TD4, all width 0.25) do **not** have equal WTE
diversity — position on the velocity axis matters.

> ⚠️ **Numbering mismatch:** the *training* envs use a different TD
> numbering (`hyper/environments/__init__.py`): `HalfCheetahVel-TaskDist1-v0`
> = [2.5, 3.0], `TaskDist2` = [0.5, 1.0], `TaskDist3` = **[0.0, 3.0] (full
> range)**. So the trained "TaskDist3" corresponds to **probe TD5**, not
> probe TD3. Keep this in mind when comparing WTE numbers to training.

### Training (full vs head vs film)

```bash
conda activate adv_rl
bash bash_scripts/run_chevel.sh                          # full/head/film on TaskDist3 = Uniform[0, 3]
RUNS="full head" bash bash_scripts/run_chevel.sh         # subset
NUM_FRAMES=2000000 NUM_PROCESSES=8 bash bash_scripts/run_chevel.sh
```

Defaults: 75M frames (the existing logs in `logs_chevel/` were stopped at
~25–27M), 16 processes, seed 73, XL policy (`policy_layers 256 128`,
state embedding 256, `policy_num_steps 400`, `max_rollouts_per_task 1`,
`lr_policy 7e-4`). The script is wired for TaskDist3 only (label
`chevel_td3_rnn_{full,head,film}`); other TDs need the env-type/label
adjusted. HN weight-divergence is **not** logged for CheetahVel
(`run_chevel.sh` does not pass `--log_hn_weight_div`, and the tracker does
not yet support continuous velocity tasks — see "HN weight divergence"
above).

**Do we have to implement it and re-run?** Not for the main result: the
full/head/film comparison rests on returns, which are already logged, and
the raw L2 is not comparable across methods anyway (different generated
parameter sizes), so its value would be as a within-method diagnostic
across task distributions — of which CheetahVel has only one trained so
far. If it is wanted, the cheap path is to implement the generic task key
and compute the divergence **offline from the saved checkpoints**
(`logs_chevel/*/models/`) on a fixed set of probe velocities, rather than
re-running 25–75M frames. Otherwise, implement it *before* any future
CheetahVel training (extra TDs or seeds) so it is logged for free then.
TODO: implement continuous-task support in
`hyper/utils/hn_weight_divergence.py` (bin target velocity as the task
key) and validate on a short smoke run.

Logs → `logs_chevel/logs_HalfCheetahVel-TaskDist3-v0/chevel_td3_rnn_{full,head,film}_*/`

**Headline result** (last-10% mean Meta-Episode Return, seed 73):
full **−35.9**, head **−58.7**, film **−35.8** — i.e. head-only collapses
(full − head ≈ **+22.8**), the largest conditioning effect in the project.
Only this one TD has been trained, at a single seed.

## Caveats

- **All training results are single-seed (73).** Method gaps of ±2–5 return
  points (GridWorld) should be treated as suggestive until replicated.
- PCA-based WTE values are only comparable *within* a notebook (separate
  PCA fits); raw `d` is the cross-notebook-safe statistic.
- GridWorld sparse-vs-dense absolute returns are not comparable (different
  reward functions) — only within-condition method gaps are.
